# Анализ разработки плагина Word-spam
> Отправка слов по одному с заданной задержкой в ExteraGram
> Источники: исходный код `Word-spam.plugin`

---

## Архитектура и принцип работы

Плагин состоит из одного класса `WordSenderSPPlugin` и вспомогательной функции `_show_copyable_error()`:

- **Хук отправки сообщения** — перехватывает исходящий текст, распознаёт команду `.sp`, проверяет аргументы и отменяет отправку самой команды.
- **Фоновый поток `word-sender`** — по очереди отправляет слова через `send_text()` и делает паузы между ними.
- **Показ ошибок** — выводит уведомление с кнопкой «Скопировать ошибку», в буфер обмена попадает полный traceback.

Формат команды:

```text
.sp [задержка_мс] слово1 слово2 слово3
```

Каждое слово уходит в чат отдельным сообщением. Настроек, страницы настроек и собственного хранилища у плагина нет: всё поведение определяется текстом команды.

---

## Ключевые решения и нюансы

### 1. Метаданные и ограничение задержки

Плагин объявляет идентификатор `ws`, название «Спамер», версию `1.1.0` и минимальную версию клиента `12.10.6`.

Максимальная задержка задана константой:

```python
MAX_DELAY_MS = 86400000
```

Это 24 часа в миллисекундах. Ограничение касается только паузы между двумя словами. Количество слов и общая длительность отправки не ограничены: при большой задержке и длинном списке один запуск может работать очень долго.

---

### 2. Подключение хука

При загрузке `on_plugin_load()` вызывает `add_on_send_message_hook()`. После этого каждое исходящее сообщение проходит через `on_send_message_hook(account, params)`.

Хук начинается с создания пустого `HookResult()`. Если сообщение не относится к команде, этот результат возвращается без изменений, и отправка продолжается обычным образом.

Если `params.message` отсутствует или не является строкой, хук также сразу возвращает пустой результат.

---

### 3. Распознавание команды `.sp`

Перед проверкой текст очищается через `strip()`, а префикс сравнивается после `lower()`. Поэтому:

- `.sp`, `.SP` и `.Sp` распознаются одинаково;
- пробелы и переводы строки в начале и конце сообщения не мешают запуску.

Следующая проверка защищает от ложных срабатываний:

```python
if len(message) > 3 and not message[3].isspace():
    return result
```

Если сразу после `.sp` идёт не пробельный символ, сообщение считается обычным текстом. Например, `.spam` и `.sport` команду не запускают.

Сообщение `.sp` без аргументов проходит эту проверку, но дальше останавливается на отсутствии слов.

---

### 4. Разбор задержки и списка слов

Текст делится через `message.split()`, то есть по любым пробельным символам, включая переводы строк. Поэтому многострочное сообщение превращается в плоский список слов, а слова с пробелами внутри невозможны.

Второй элемент списка пробуется как число:

```python
try:
    delay_ms = int(parts[1])
    words = parts[2:]
except (TypeError, ValueError):
    delay_ms = 0
    words = parts[1:]
```

Если число получить не удалось, задержка считается нулевой, а второй элемент становится первым словом. Примеры:

```text
.sp 500 привет мир    → задержка 500 мс, слова: привет, мир
.sp привет мир        → задержка 0 мс, слова: привет, мир
.sp 500               → ошибка: нет слов
.sp 100 200           → задержка 100 мс, слово: 200
.sp 1_000 слово       → int("1_000") = 1000, задержка 1000 мс
.sp -1 слово          → задержка -1, ошибка диапазона
```

Из этого следуют два нюанса:

- первое слово, состоящее из цифр, будет воспринято как задержка; чтобы отправить число первым словом, нужно явно указать задержку: `.sp 0 123`;
- запись вида `-1` или `+5` тоже разбирается как число, поэтому отрицательное значение приводит к ошибке диапазона, а не отправляется как слово.

---

### 5. Проверки и отмена исходного сообщения

Последовательно выполняются проверки:

- в команде есть хотя бы один аргумент после `.sp`;
- после выделения задержки осталось хотя бы одно слово;
- задержка находится в диапазоне от `0` до `MAX_DELAY_MS`;
- `params.peer` определён.

При любой ошибке вызывается `_show_copyable_error()`, а в результат записывается:

```python
result.strategy = HookStrategy.CANCEL
```

`CANCEL` останавливает отправку исходного сообщения. Поэтому текст команды `.sp ...` в чат не попадает ни при ошибке, ни при успешном запуске.

Идентификатор чата берётся из `params.peer` без дополнительных преобразований и передаётся в поток как `peer_id`. Если `peer` не определён, запуск отменяется с сообщением «Не удалось определить текущий чат».

---

### 6. Запуск фонового потока

После успешной проверки стратегия `CANCEL` устанавливается до запуска потока, затем создаётся поток:

```python
worker = threading.Thread(
    target=self._send_words,
    args=(peer_id, words, delay_ms),
    daemon=True,
    name="word-sender",
)
worker.start()
```

Хук сразу возвращает результат и не ждёт окончания отправки. Благодаря этому поле ввода и интерфейс не блокируются на время пауз между словами.

Поток помечен как `daemon=True`, поэтому он не удерживает процесс приложения от завершения. Имя `word-sender` упрощает поиск потока в диагностике.

---

### 7. Цикл отправки и паузы

`_send_words()` переводит задержку в секунды и проходит по списку слов:

```python
delay_seconds = delay_ms / 1000.0
```

Для каждого слова вызывается `send_text(peer_id, word)`. Пауза выполняется через `time.sleep()` только при двух условиях:

- слово не последнее;
- `delay_seconds` не равен нулю.

Из этого следует:

- после последнего слова лишней паузы нет;
- при задержке `0` слова отправляются подряд без ожидания, и плагин не контролирует темп отправки;
- реакция на ограничения Telegram по частоте отправки в коде не предусмотрена; отдельной обработки таких случаев нет.

---

### 8. Показ и копирование ошибок

`_show_copyable_error(message, error)` формирует полный текст traceback через `traceback.format_exception()` и показывает уведомление через `BulletinHelper.show_with_button()`.

В уведомлении используются:

- иконка `R.raw.error`, полученная через `jclass("org.telegram.messenger.R")`;
- кнопка «Скопировать ошибку»;
- обработчик нажатия, который вызывает `copy_to_clipboard(details)`.

У функции есть два уровня запасного поведения: если показ уведомления с кнопкой не удался, вызывается `BulletinHelper.show_error()` с текстом `сообщение: ошибка`; если не удался и он, исключение подавляется.

Ошибки валидации создаются как `ValueError` или `RuntimeError`, но не выбрасываются через `raise`. У такого исключения нет сохранённого трейсбэка, поэтому в копируемый текст попадает только строка вида `ValueError: ...` без цепочки вызовов. Для ошибок отправки, пойманных в `except`, трейсбэк содержит реальный стек.

Показ уведомления при ошибке отправки выполняется из рабочего потока. Исходный код не оборачивает этот вызов в `run_on_ui_thread()`: нужная работа с UI-потоком, если она требуется, должна выполняться внутри `BulletinHelper`, а из этого файла это не видно.

---

### 9. Прерывание отправки при ошибке

Вызов `send_text()` обёрнут в `try/except`. При исключении плагин показывает ошибку с номером слова:

```python
"Не удалось отправить слово " + str(index + 1)
```

После этого выполняется `return`, и оставшиеся слова не отправляются.

Проверяются только исключения. Возвращаемое значение `send_text()` не анализируется, поэтому, если функция сообщает о проблеме без исключения, плагин этого не заметит. Успешное завершение тоже ничем не подтверждается: итогового уведомления нет.

---

### 10. Отсутствие остановки и выгрузки

В плагине нет `on_plugin_unload()` и механизма отмены запущенной отправки. Это означает:

- запущенный поток не хранится в атрибуте и не регистрируется нигде;
- флага остановки или события вроде `threading.Event` нет;
- после отключения плагина уже работающий поток продолжит отправлять оставшиеся слова;
- остановить отправку без завершения процесса приложения нельзя.

Новые команды после отключения не распознаются, но уже созданные потоки продолжают работу независимо от состояния плагина.

---

### 11. Параллельные запуски

Каждая команда `.sp` создаёт отдельный поток. Общего реестра, блокировки или очереди нет, поэтому несколько запущенных команд работают одновременно.

Если команды запущены в одном чате, их слова чередуются в зависимости от задержек и момента вызова `send_text()`. Если команды запущены в разных чатах, потоки не влияют друг на друга, поскольку `peer_id` передаётся каждому потоку отдельно.

---

## Общая схема работы

```text
on_plugin_load()
    │
    └── add_on_send_message_hook()

on_send_message_hook(account, params)
    │
    ├── message не строка ───────────────► пропуск
    ├── нет префикса .sp ────────────────► пропуск
    ├── после .sp не пробел (.spam) ─────► пропуск
    │
    ▼
 message.split()
    │
    ├── меньше двух элементов ───────────► ошибка + CANCEL
    │
    ▼
 int(parts[1])
    │
    ├── число ───► delay_ms = число, words = parts[2:]
    └── не число ► delay_ms = 0, words = parts[1:]
    │
    ├── слов нет ────────────────────────► ошибка + CANCEL
    ├── задержка вне 0..86400000 ────────► ошибка + CANCEL
    ├── params.peer отсутствует ─────────► ошибка + CANCEL
    │
    ▼
 CANCEL (команда не уходит в чат)
    │
    ▼
 поток word-sender
    │
    ▼
_send_words(peer_id, words, delay_ms)
    │
    ├── send_text(peer_id, слово)
    │       │
    │       └── исключение → ошибка + выход из цикла
    │
    └── пауза time.sleep(), если слово не последнее
        и задержка не равна нулю
```

---

## Важные особенности

- Команда распознаётся без учёта регистра и только если после `.sp` идёт пробельный символ или конец сообщения.
- Текст команды в чат не отправляется: хук всегда возвращает `CANCEL` при распознанной команде.
- Задержка необязательна: если вторым элементом не число, она считается нулевой.
- Первое слово из цифр воспринимается как задержка; для отправки числа первым словом нужно сначала указать задержку.
- Отрицательное значение, например `-1`, воспринимается как задержка и приводит к ошибке диапазона.
- Допустимая задержка — от `0` до `86400000` мс; количество слов и общее время отправки не ограничены.
- При задержке `0` слова отправляются без пауз, а отдельной защиты от ограничений Telegram нет.
- Разбор через `split()` убирает переводы строк и не позволяет отправлять слова с пробелами внутри.
- Отправка идёт в отдельном daemon-потоке, интерфейс не блокируется.
- Первая ошибка `send_text()` останавливает отправку оставшихся слов.
- Ошибки валидации создаются без `raise`, поэтому в копируемом тексте нет цепочки вызовов.
- Запущенную отправку нельзя остановить, а выгрузка плагина не завершает уже работающие потоки.
- Параллельные команды `.sp` не координируются между собой.
