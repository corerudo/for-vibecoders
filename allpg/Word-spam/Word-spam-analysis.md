# Анализ разработки плагина Word-spam
> Отправка слов по одному с заданной задержкой в ExteraGram
> Источники: исходный код `Word-spam.plugin`

---

## Архитектура и принцип работы

Плагин состоит из класса `WordSenderSPPlugin`, небольшого класса задачи `_SendJob` и вспомогательных функций `_show_copyable_error()`, `_notify()` и `_is_command()`:

- **Хук отправки сообщения** — перехватывает исходящий текст, распознаёт команды `.sp` и `.stsp`, проверяет аргументы и отменяет отправку самой команды.
- **Фоновый поток `word-sender`** — по очереди отправляет слова через `send_text()` и делает паузы между ними.
- **Реестр активных задач** — список `_jobs` с блокировкой `_lock`; каждая задача хранит чат и событие остановки.
- **Показ ошибок и уведомлений** — ошибки выводятся с кнопкой «Скопировать ошибку», в буфер обмена попадает полный traceback.

Формат команд:

```text
.sp [задержка_мс] слово1 слово2 слово3
.stsp
.stsp all
```

Каждое слово уходит в чат отдельным сообщением. `.stsp` останавливает отправку в текущем чате, `.stsp all` — во всех чатах. Настроек, страницы настроек и собственного хранилища у плагина нет: всё поведение определяется текстом команды.

---

## Ключевые решения и нюансы

### 1. Метаданные и ограничение задержки

Плагин объявляет идентификатор `ws`, название «Спамер», версию `1.2.0` и минимальную версию клиента `12.10.6`. В описании указаны оба формата команд.

Максимальная задержка задана константой:

```python
MAX_DELAY_MS = 86400000
```

Это 24 часа в миллисекундах. Ограничение касается только паузы между двумя словами. Количество слов и общая длительность отправки не ограничены: при большой задержке и длинном списке один запуск может работать очень долго, пока его не остановят.

---

### 2. Подключение хука и состояние плагина

При загрузке `on_plugin_load()` создаёт реестр задач и блокировку, после чего вызывает `add_on_send_message_hook()`:

```python
self._jobs = []
self._lock = threading.Lock()
self.add_on_send_message_hook()
```

После этого каждое исходящее сообщение проходит через `on_send_message_hook(account, params)`.

Хук начинается с создания пустого `HookResult()`. Если сообщение не относится к командам плагина, этот результат возвращается без изменений, и отправка продолжается обычным образом. Если `params.message` отсутствует или не является строкой, хук также сразу возвращает пустой результат.

---

### 3. Распознавание команд

Перед проверкой текст очищается через `strip()`. Сравнение префикса выполняется в функции `_is_command()`:

```python
def _is_command(message, command):
    if not message.lower().startswith(command):
        return False
    return len(message) == len(command) or message[len(command)].isspace()
```

Команда считается распознанной, если сообщение начинается с её имени без учёта регистра, а сразу за именем идёт пробельный символ или текст заканчивается. Поэтому:

- `.sp`, `.SP` и `.Sp` распознаются одинаково;
- пробелы и переводы строк в начале и конце сообщения не мешают запуску;
- `.spam`, `.sport` и `.stspx` командами не считаются и уходят в чат как обычный текст.

Сначала проверяется `.stsp`, затем `.sp`. Конфликта между ними нет: `.stsp` не начинается с `.sp`.

Сообщение `.sp` без аргументов распознаётся как команда, но дальше останавливается на отсутствии слов.

---

### 4. Разбор задержки и списка слов

Текст делится через `message.split()`, то есть по любым пробельным символам, включая переводы строк. Поэтому многострочное сообщение превращается в плоский список слов, а слова с пробелами внутри невозможны.

Второй элемент списка пробуется как число:

```python
try:
    delay_ms = int(parts[1])
    words = parts[2:]
except (TypeError, ValueError):
    delay_ms = 0
    words = parts[1:]
```

Если число получить не удалось, задержка считается нулевой, а второй элемент становится первым словом. Примеры:

```text
.sp 500 привет мир    → задержка 500 мс, слова: привет, мир
.sp привет мир        → задержка 0 мс, слова: привет, мир
.sp 500               → ошибка: нет слов
.sp 100 200           → задержка 100 мс, слово: 200
.sp 1_000 слово       → int("1_000") = 1000, задержка 1000 мс
.sp -1 слово          → задержка -1, ошибка диапазона
```

Из этого следуют два нюанса:

- первое слово, состоящее из цифр, будет воспринято как задержка; чтобы отправить число первым словом, нужно явно указать задержку: `.sp 0 123`;
- запись вида `-1` или `+5` тоже разбирается как число, поэтому отрицательное значение приводит к ошибке диапазона, а не отправляется как слово.

---

### 5. Проверки и отмена исходного сообщения

Для `.sp` последовательно выполняются проверки:

- в команде есть хотя бы один аргумент после `.sp`;
- после выделения задержки осталось хотя бы одно слово;
- задержка находится в диапазоне от `0` до `MAX_DELAY_MS`;
- `params.peer` определён.

При любой ошибке вызывается `_show_copyable_error()`, а в результат записывается:

```python
result.strategy = HookStrategy.CANCEL
```

`CANCEL` останавливает отправку исходного сообщения. Поэтому текст команды в чат не попадает ни при ошибке, ни при успешном запуске. Это относится и к `.stsp`: стратегия `CANCEL` устанавливается в самом начале обработки остановки.

Идентификатор чата берётся из `params.peer` без дополнительных преобразований. Если `peer` не определён, запуск отменяется с сообщением «Не удалось определить текущий чат».

---

### 6. Реестр задач и запуск потока

Каждая отправка описывается объектом `_SendJob`, который хранит идентификатор чата и событие остановки:

```python
class _SendJob:
    def __init__(self, peer_id):
        self.peer_id = peer_id
        self.stop_event = threading.Event()
```

После успешной проверки стратегия `CANCEL` устанавливается до запуска потока, задача добавляется в `_jobs` под блокировкой, затем создаётся и запускается поток:

```python
worker = threading.Thread(
    target=self._send_words,
    args=(job, words, delay_ms),
    daemon=True,
    name="word-sender",
)
```

Если запустить поток не удалось, задача удаляется из реестра, а пользователь получает ошибку «Не удалось запустить отправку». Так в списке не остаётся записей о потоках, которых нет.

Хук сразу возвращает результат и не ждёт окончания отправки. Благодаря этому поле ввода и интерфейс не блокируются на время пауз между словами. Поток помечен как `daemon=True`, поэтому он не удерживает процесс приложения от завершения, а имя `word-sender` упрощает поиск потока в диагностике.

---

### 7. Цикл отправки и паузы

`_send_words()` переводит задержку в секунды и проходит по списку слов. Перед каждой отправкой проверяется событие остановки:

```python
if job.stop_event.is_set():
    return
```

Для слова вызывается `send_text(job.peer_id, word)`. Пауза между словами выполняется не через `time.sleep()`, а через ожидание события:

```python
if index < last_index and delay_seconds:
    if job.stop_event.wait(delay_seconds):
        return
```

`Event.wait()` блокирует поток на заданное время, но просыпается сразу после установки события. Поэтому остановка срабатывает мгновенно даже при очень большой задержке, а не по окончании паузы.

Пауза выполняется только при двух условиях:

- слово не последнее;
- `delay_seconds` не равен нулю.

Из этого следует:

- после последнего слова лишней паузы нет;
- при задержке `0` слова отправляются подряд без ожидания, а остановка проверяется перед каждым словом;
- реакция на ограничения Telegram по частоте отправки в коде не предусмотрена; отдельной обработки таких случаев нет.

Весь цикл обёрнут в `try/finally`. Блок `finally` при любом выходе — завершении списка, остановке или ошибке — удаляет задачу из `_jobs` под блокировкой.

---

### 8. Команда остановки `.stsp`

`_handle_stop()` разбирает команду и определяет область остановки:

- `.stsp` — задачи текущего чата, сравнение идёт по `params.peer`;
- `.stsp all` — все активные задачи независимо от чата;
- любые другие аргументы — ошибка «Неверный формат остановки».

Для варианта без `all` требуется определённый `params.peer`, иначе показывается ошибка «Не удалось определить текущий чат». Для `.stsp all` чат не нужен.

Остановку выполняет `_stop_jobs()`:

```python
def _stop_jobs(self, peer_id=None):
    with self._lock:
        targets = [
            job
            for job in self._jobs
            if not job.stop_event.is_set() and (peer_id is None or job.peer_id == peer_id)
        ]
    for job in targets:
        job.stop_event.set()
    return len(targets)
```

Список подходящих задач собирается под блокировкой, а события устанавливаются уже после её освобождения. Задачи, у которых остановка уже запрошена, в подсчёт не попадают, поэтому повторная команда не засчитывает их заново.

Результат показывается через `_notify()`: «Остановлено отправок: N» либо «Нет активной отправки», если останавливать было нечего.

Остановка срабатывает на ближайшей проверке события: перед следующим словом или во время паузы. Слово, которое уже передано в `send_text()`, отменить нельзя.

---

### 9. Показ и копирование ошибок

`_show_copyable_error(message, error)` формирует полный текст traceback через `traceback.format_exception()` и показывает уведомление через `BulletinHelper.show_with_button()`.

В уведомлении используются:

- иконка `R.raw.error`, полученная через `jclass("org.telegram.messenger.R")`;
- кнопка «Скопировать ошибку»;
- обработчик нажатия, который вызывает `copy_to_clipboard(details)`.

У функции есть два уровня запасного поведения: если показ уведомления с кнопкой не удался, вызывается `BulletinHelper.show_error()` с текстом `сообщение: ошибка`; если не удался и он, исключение подавляется.

Ошибки валидации создаются как `ValueError` или `RuntimeError`, но не выбрасываются через `raise`. У такого исключения нет сохранённого трейсбэка, поэтому в копируемый текст попадает только строка вида `ValueError: ...` без цепочки вызовов. Для ошибок отправки, пойманных в `except`, трейсбэк содержит реальный стек.

Обычные сообщения о результате остановки выводятся через `_notify()`, который вызывает `BulletinHelper.show_info()` и подавляет любое исключение. Если такой вызов недоступен, уведомление просто не появится, но на работу остановки это не влияет.

Показ уведомления при ошибке отправки выполняется из рабочего потока. Исходный код не оборачивает этот вызов в `run_on_ui_thread()`: нужная работа с UI-потоком, если она требуется, должна выполняться внутри `BulletinHelper`, а из этого файла это не видно.

---

### 10. Прерывание отправки при ошибке

Вызов `send_text()` обёрнут в `try/except`. При исключении плагин показывает ошибку с номером слова:

```python
"Не удалось отправить слово " + str(index + 1)
```

После этого выполняется `return`, и оставшиеся слова не отправляются. Блок `finally` при этом всё равно убирает задачу из реестра.

Проверяются только исключения. Возвращаемое значение `send_text()` не анализируется, поэтому, если функция сообщает о проблеме без исключения, плагин этого не заметит. Успешное завершение тоже ничем не подтверждается: итогового уведомления нет.

---

### 11. Выгрузка плагина

`on_plugin_unload()` вызывается при отключении плагина и при закрытии приложения. Он останавливает все активные задачи:

```python
def on_plugin_unload(self):
    self._stop_jobs()
```

Вызов без аргумента означает область «все чаты». Метод только устанавливает события остановки и не дожидается завершения потоков, поэтому выгрузка не блокируется.

Каждый поток завершается самостоятельно: спящий в `Event.wait()` просыпается сразу, а поток внутри `send_text()` выходит на следующей проверке события. После выгрузки не остаётся потоков, которые продолжали бы отправлять слова.

Снятие хука отправки в коде явно не выполняется, этим занимается механизм плагинов. Если вызов `send_text()` уже начался, он завершится в обычном порядке: прервать его плагин не может.

---

### 12. Параллельные запуски

Каждая команда `.sp` создаёт отдельную задачу и отдельный поток. Очереди нет, поэтому несколько запущенных команд работают одновременно.

Если команды запущены в одном чате, их слова чередуются в зависимости от задержек и момента вызова `send_text()`; `.stsp` в этом чате остановит их все разом. Если команды запущены в разных чатах, потоки не влияют друг на друга, поскольку `peer_id` хранится в каждой задаче отдельно, а `.stsp` без `all` затрагивает только текущий чат.

Доступ к реестру задач защищён блокировкой, поэтому одновременный запуск, остановка и завершение потоков не повреждают список.

## Общая схема работы

```text
on_plugin_load()
    │
    ├── _jobs = [], _lock
    └── add_on_send_message_hook()

on_send_message_hook(account, params)
    │
    ├── message не строка ───────────────► пропуск
    │
    ├── .stsp ───────────────────────────► _handle_stop()
    │       │
    │       ├── CANCEL (команда не уходит в чат)
    │       ├── аргумент не all ─────────► ошибка формата
    │       ├── без all и нет peer ──────► ошибка чата
    │       └── _stop_jobs(peer или все)
    │               │
    │               ├── stop_event.set() у подходящих задач
    │               └── уведомление: N остановлено / нет активной
    │
    ├── не .sp (.spam и др.) ────────────► пропуск
    │
    ▼
 message.split()
    │
    ├── меньше двух элементов ───────────► ошибка + CANCEL
    │
    ▼
 int(parts[1])
    │
    ├── число ───► delay_ms = число, words = parts[2:]
    └── не число ► delay_ms = 0, words = parts[1:]
    │
    ├── слов нет ────────────────────────► ошибка + CANCEL
    ├── задержка вне 0..86400000 ────────► ошибка + CANCEL
    ├── params.peer отсутствует ─────────► ошибка + CANCEL
    │
    ▼
 CANCEL (команда не уходит в чат)
    │
    ├── _SendJob(peer_id) → _jobs
    ▼
 поток word-sender
    │
    ▼
_send_words(job, words, delay_ms)
    │
    ├── stop_event установлен ───────────► выход
    ├── send_text(peer_id, слово)
    │       │
    │       └── исключение → ошибка + выход из цикла
    ├── пауза stop_event.wait(задержка)
    │       │
    │       └── событие установлено ─────► выход
    │
    └── finally: удаление задачи из _jobs

on_plugin_unload()
    │
    └── _stop_jobs() ────────────────────► stop_event.set() у всех задач
```

## Важные особенности

- Команды `.sp` и `.stsp` распознаются без учёта регистра и только если за именем идёт пробельный символ или конец сообщения.
- Текст команд в чат не отправляется: хук всегда возвращает `CANCEL` при распознанной команде.
- Задержка необязательна: если вторым элементом не число, она считается нулевой.
- Первое слово из цифр воспринимается как задержка; для отправки числа первым словом нужно сначала указать задержку.
- Отрицательное значение, например `-1`, воспринимается как задержка и приводит к ошибке диапазона.
- Допустимая задержка — от `0` до `86400000` мс; количество слов и общее время отправки не ограничены.
- При задержке `0` слова отправляются без пауз, а отдельной защиты от ограничений Telegram нет.
- Разбор через `split()` убирает переводы строк и не позволяет отправлять слова с пробелами внутри.
- Отправка идёт в отдельном daemon-потоке, интерфейс не блокируется.
- Каждая отправка описывается задачей с собственным событием остановки; реестр задач защищён блокировкой.
- `.stsp` останавливает отправки текущего чата, `.stsp all` — всех чатов.
- Остановка прерывает паузу сразу, но не отменяет слово, которое уже передано в `send_text()`.
- Первая ошибка `send_text()` останавливает отправку оставшихся слов, задача при этом удаляется из реестра.
- Ошибки валидации создаются без `raise`, поэтому в копируемом тексте нет цепочки вызовов.
- При выгрузке плагин останавливает все активные отправки и не ждёт завершения потоков.
- Параллельные команды `.sp` в одном чате чередуют слова, в разных чатах работают независимо.
